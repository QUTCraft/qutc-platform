# QUTCraft Platform 需求范围 v1

> 状态：比赛版冻结基线
> 冻结日期：2026-07-17  
> 实现同步：2026-08-05
> 覆盖范围：2026-08-31 MVP 与比赛演示

## 1. 产品定义

QUTCraft Platform 是一套面向校园社团与民间组织的 AI 活动策划、内容与协作平台。系统由公开门户、内部管理工作台、组织运营智能体、通用组织能力和可选行业适配器组成。QUTCraft Minecraft 社团是第一方真实场景，而不是通用核心的唯一业务假设。

系统的核心价值是让组织把公开传播、资源分发、知识沉淀和内部协作放在同一套数据与权限模型之下，并让 AI 在用户显式选择的组织知识范围内生成带引用活动方案。AI 只能提出受控建议，项目、里程碑和公告草稿必须经人工批准，内容仍需人工发布；每个组织同时可以保留自己的公开呈现风格。

## 2. 范围与边界

### 2.1 MVP 内的能力

| 模块 | MVP 能力 | 公开/管理边界 |
| --- | --- | --- |
| 公开门户 | 组织介绍、动态、项目、资源、知识库入口与加入申请 | 仅读取已发布的公开字段。 |
| 内容管理 | Markdown 草稿、原作者提交审核、管理员发布/退回、申请下线、不可变修订/恢复；资源元数据、受控分发与下载统计 | 管理端处理，门户只消费发布结果。基础单级审核已实现，完整多级会签仍延期。 |
| 身份与成员 | 注册/登录、成员关系、角色与权限、单个/批量邀请、多组织切换和默认组织偏好 | 内部数据，服务端 RBAC 授权。 |
| 项目与知识库 | 项目状态、负责人、成员、里程碑和公开摘要；知识目录、文章分类与发布 | 公开数据须显式标记可见。项目任务/评论不进入 MVP。 |
| 审核与通知 | 通用成员/白名单申请、通过、拒绝、审计、审批通知 Outbox 和组织邀请模板 | 申请可从门户进入；处理、通知状态和模板只在后台。 |
| 自定义门户 | 默认 MD3 门户、Portal Manifest v1、主题 Token、回退 | 自定义门户仅使用公开 Portal API。 |
| AI 活动服务 | 组织知识检索、带引用活动方案、持久化运行状态、五维人工评分和领域专用建议批准 | AI 不自动发布、不审批申请、不修改角色、不执行任意外部命令。 |

### 2.2 明确不在本次 MVP 内

- 多服务器集群编排、任意第三方插件代码执行和复杂跨组织工作流。
- 协同富文本、在线文档冲突合并、实时聊天与任意脚本化自动化。
- 项目任务看板/评论/工时、全文索引、资源分片上传与统计报表。
- 密码找回、邮箱验证、2FA、SSO，以及面向公网的完整 SaaS 生命周期。
- 通用 AgentToolCall/工作流设计器、公开问答、多智能体协作和 AI 自动执行高风险动作。
- 将对象存储集群或基础设施复杂度作为产品卖点。
- 任何通过前端隐藏、前端路由守卫或主题代码替代服务端权限校验的方案。

## 3. 用户与角色

| 角色 | 典型目标 | 关键能力 |
| --- | --- | --- |
| 访客 | 了解组织并获取公开资源 | 浏览门户、查看公开状态、跳转申请入口。 |
| 注册用户 | 加入组织或申请白名单 | 登录、提交申请；SMTP 启用时通过邮箱接收审批结果。当前不提供公开申请状态查询。 |
| 成员 | 参与组织项目和知识沉淀 | 查看授权项目与内部资料。 |
| 内容编辑 | 维护组织传播内容 | 创建、编辑、提交内容，查看内容状态。 |
| 项目负责人 | 推进项目公开与成员协作 | 管理被授权项目及公开摘要。 |
| 审核员 | 处理加入和白名单申请 | 通过/拒绝申请并留下审计记录。 |
| 管理员 | 维护组织运行边界 | 管理角色、内容发布、申请审核与组织配置。 |
| 活动策划者/评审人 | 使用组织知识规划活动并评估输出质量 | 生成带引用方案、查看历史、五维评分；具备额外业务权限时人工批准建议。 |

角色名称是产品语言；服务端实施必须映射为 `resource:action` 权限，不得将“管理员”作为不透明布尔值。完整矩阵见 [RBAC 权限矩阵](../architecture/rbac-matrix.md)。

## 4. MVP 用户故事

### 4.1 公开门户

1. 作为访客，我可以在不登录的情况下浏览组织介绍、动态、项目、资源和知识库，因此能判断组织是否值得关注。
2. 作为访客，我可以看到明确的加入申请入口，因此能联系组织但不会获得内部管理信息。
3. 作为门户开发者，我可以仅凭 Portal API 和 Manifest 开发自定义展示主题，因此组织不需要修改核心业务代码就能保留文化表达。

### 4.2 内容与协作

1. 作为内容编辑，我可以创建草稿并看到其审核/发布状态，因此未完成内容不会误出现在门户。
2. 作为管理员，我可以发布或下线内容；门户随后只读取发布结果，因此公开层和管理层职责清晰。
3. 作为项目负责人，我可以维护项目公开摘要和状态，因此门户能展示可信的项目进展。

### 4.3 申请审核与通知

1. 作为申请人，我可以提交成员或白名单申请，因此不必通过口头渠道追踪进度。
2. 作为审核员，我可以通过或拒绝申请并留下可追踪记录，因此团队能复盘决定。
3. 作为管理员，我可以追踪审批结果通知的投递状态并安全重试，因此通知失败不会污染审批事实。

### 4.4 AI 活动策划与人工执行

1. 作为活动策划者，我可以填写结构化活动需求并显式选择当前组织知识，因此模型上下文可解释且不会跨组织取数。
2. 作为策划者，我可以获得带固定引用、模型和 Prompt 版本的活动方案，并在刷新后从历史恢复，因此长任务和评审证据不会只存在浏览器内存。
3. 作为具备项目与内容权限的管理员，我可以逐项批准建议，在一个事务中创建非公开项目、里程碑和公告草稿；未选择、越权或失败的操作不会留下半成品。
4. 作为评审人，我可以保存自己的五维评分，组织只能查看脱敏质量汇总；评分不会自动批准、发布或改变业务状态。

## 5. 领域范围

| 领域对象 | 说明 | 当前公开方式 |
| --- | --- | --- |
| Organization | 组织资料、公开标识与门户配置 | Portal 返回公开名称、介绍、外链。 |
| User / Membership | 用户身份与组织成员关系 | 仅 Admin 返回授权范围内数据。 |
| Role / Permission | RBAC 权限集合 | 不对 Portal 暴露。 |
| Content / Post | 动态、公告、页面等内容 | 仅 `published` 且公开的摘要进入 Portal。 |
| Project | 项目协作与公开展示 | Portal 返回公开摘要、标签和状态。 |
| KnowledgeArticle | 组织知识沉淀 | Portal 返回已发布文章元数据。 |
| Asset / Resource | 文件、模板、资源元数据与下载计数 | 下载地址由服务端提供受控 API 路径，不暴露对象键或存储凭据。 |
| ContentRevision | 内容不可变版本快照 | 仅 Admin 按当前组织读取/恢复；不进入 Portal。 |
| Application | 成员或白名单申请 | 处理状态仅对管理端可见；审批结果可通过通知适配器发送。 |
| NotificationOutbox | 审批结果通知事件、状态与重试 | 仅组织配置权限可见，不进入 Portal。 |
| AuditEvent | 高风险操作审计 | 不对 Portal 暴露。 |
| AgentRun / ActivityPlan | 智能体运行、引用、活动方案、评分与批准结果 | 仅当前组织和具备 `ai:use` 的成员可见。 |

## 6. 数据可见性规则

- 所有组织级数据必须具备 `organization_id` 并按租户范围查询。
- 内容在未发布前必须不可被 Portal API、搜索索引、公开缓存或自定义门户读取。
- 邮箱、角色、申请说明、审核人、审计记录、对象键与签名 URL 生命周期均视为内部数据。
- 公开资源的下载能力由服务端重新签发；资源 ID 不能作为对象存储路径或访问凭据。
- 自定义门户与默认门户享有同一公开数据范围，不获得后台的额外能力。

## 7. 功能优先级

| 优先级 | 范围 | 原则 |
| --- | --- | --- |
| P0 | 公开门户、身份/RBAC、内容发布闭环、申请审核与通知、AI 活动服务闭环、API 契约 | 8 月 31 日前必须可演示。 |
| P1 | 项目/知识库协作、资源上传、通知首版、内容修订、门户 Manifest 预览与回退 | 不阻塞 P0 演示，但优先完成。 |
| P2 | 复杂编辑器、自动化工作流、插件生态 | 仅记录为赛后方向。 |

## 8. 非功能要求

| 类别 | MVP 要求 |
| --- | --- |
| 安全 | 所有 Admin 写请求服务端鉴权、组织范围校验和审计；敏感凭据不进入浏览器。 |
| 可用性 | 门户、后台表格与表单具备加载、空、失败和权限拒绝状态。 |
| 可观测性 | API 返回 `request_id`；审核、发布、下载、通知重试和智能体运行/批准均可关联日志。 |
| 可演示性 | Docker 环境可以独立完成核心闭环。 |
| 可扩展性 | 新门户使用 Manifest 与 Portal API；外部服务通过受控后端集成接入。 |
| 兼容性 | API 破坏性变更新增版本；门户加载失败回退至默认 MD3。 |

## 9. 冻结与变更规则

本文件冻结 MVP 的产品边界，不冻结具体实现细节。新增需求必须说明：目标用户、是否改变公开/内部边界、所需权限、数据迁移、API 契约、验收方式及是否影响 8 月 31 日演示。未写清上述内容的需求只能进入 P2 候选池。
