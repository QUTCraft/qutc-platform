# 服务创新类比赛叙事一页纸

> 方向冻结：2026-08-01

## 项目名称

**社团智枢 Commons Agent：面向校园组织的 AI 活动策划与运营服务平台**

## 一句话定位

把社团活动从“临时群聊里写策划”升级为“组织知识 → AI 活动方案 → 人工批准 → 项目与宣传执行 → 总结沉淀”的可审查服务闭环。

## 校园问题

校园社团举办活动时，需要反复查找历史材料和校园规范，手工编写策划、分工、宣传和总结。资料散落在群聊、网盘与个人文档中，活动经验难以复用，执行责任也难以追踪。通用聊天机器人可以写一段文字，却不了解组织资料、不能形成可执行对象，也缺少权限和审计。

## 核心方案

1. 组织成员用结构化向导提交活动目标、受众、时间、场地、预算和风险约束。
2. 活动策划智能体只读取用户明确选择的当前组织知识，生成带固定引用的标准 Markdown 方案。
3. 系统提出创建项目、里程碑和宣传草稿的类型化建议，由用户逐项批准。
4. 批准操作在服务端事务中执行并写入审计；项目默认不公开，内容固定为草稿，AI 永不自动发布。
5. CMS、项目和知识库承接后续执行、宣传、复盘与经验沉淀。

## 为什么不是“CMS 加一个 AI 按钮”

AI 活动工作台是比赛主入口，CMS 是智能体安全落地的执行底座。智能体拥有知识读取和低风险建议能力，但不替代 RBAC、内容状态机、人工审批或外部适配器。每次生成都能回答“使用了哪些资料、由谁批准、最终创建了什么”。

## 技术创新

- **权限感知检索**：当前组织、`knowledge:read` 与用户显式选择共同限定上下文。
- **引用快照**：保存标题、摘要和资料版本时间，避免后续内容变化使结果无法复核。
- **类型化建议操作**：模型不能拼接任意 URL、SQL 或 Shell；项目、里程碑和草稿使用固定 Schema。
- **人工确认与事务执行**：建议可以部分批准，依赖关系由服务端验证，重复批准返回冲突。
- **供应商中立**：支持 OpenAI-compatible 真实模型和明确标识的开发 Mock；生产环境拒绝 Mock。
- **可追踪治理**：配额、超时、取消、RBAC、审计、Request ID 和失败降级进入同一闭环。

## 真实验证场景

QUTCraft 是青岛理工大学 Minecraft 社团，也是第一个真实用户。演示可围绕“校园开源创作工作坊”或“社团暑期共创活动”：智能体读取活动规范和历史复盘，生成方案，经负责人批准后创建项目、准备/宣传/执行/复盘里程碑及门户公告草稿。相同能力也适用于摄影社、志愿团队和技术社群。

## 主演示路径

1. 打开“AI 校园活动策划”，填写活动需求。
2. 检索并选择校园活动规范和历史活动资料。
3. 使用真实模型生成方案，查看固定引用、模型状态和 Request ID。
4. 逐项批准项目、里程碑和公告草稿。
5. 在项目管理与内容编辑器查看创建结果，证明没有自动公开。
6. 人工检查并发布公告，在 Portal 查看，再通过审计记录回溯全过程。

## 评审价值

- **创意**：AI 输出直接衔接组织执行对象，而不是停留在聊天文本。
- **实用**：减少策划、分工、宣传和复盘的重复劳动，保留组织经验。
- **完整**：从需求、知识、生成、批准、执行到公开传播形成闭环。
- **体验**：分步向导、引用核对、逐项批准、失败提示和移动端适配。
- **可落地**：可在单台服务器通过 Compose 部署，并可用不同组织演示资料复现。
