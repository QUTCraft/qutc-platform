# 比赛叙事一页纸

## 项目名称

**QUTCraft Platform：面向校园社团与民间组织的可扩展内容与协作平台**

## 一句话定位

让组织用统一的数据、权限和内容能力完成对外传播与内部协作，同时保留可替换的特色门户。

## 问题

校园社团和民间组织的公告、资源、项目资料、知识经验与成员协作常分散在多个聊天群、网盘、文档和临时页面中。即使有官网，它通常只是静态宣传页，无法与内容生产、资源分发、申请审核和组织管理形成可靠闭环。

## 方案

平台把系统分为两个职责明确的面：

1. **公开门户**：面向访客的宣传、资源分发与公开知识入口，只消费已发布公开数据。
2. **管理工作台**：面向组织成员的内容、成员、项目、审核和可选服务器适配操作，所有敏感动作经 JWT、RBAC 和审计保护。

两者通过 OpenAPI 契约连接，而不是通过“在官网里藏一个后台入口”耦合。默认门户使用 MD3；组织可依照 Manifest 和公开 Portal API 自建门户主题。

## 真实场景验证

QUTCraft 是青岛理工大学的 Minecraft 社团。它需要一个能展示社团文化、项目、资源和服务器公开状态的官网，也需要一个能够处理内容发布、白名单申请与服务器联动的内部系统。项目将 Minecraft 风格门户和 RCON 能力放在可替换主题与服务端适配器层，因此同一核心也能服务摄影社、志愿团队、技术社群等组织。

## 技术亮点

- **API-first**：Portal 与 Admin 的 OpenAPI 3.1 契约、统一响应、错误码和分页语义可直接导入 Apifox/Swagger。
- **安全分层**：公开数据与内部数据分前缀、分权限、分审计；浏览器不接触 RCON、数据库或对象存储长期密钥。
- **门户可替换**：Manifest 限制自定义门户只能使用公开能力，加载失败自动回退 MD3。
- **适配器而非硬编码**：Minecraft 服务器通过 `ServerAdapter` 接入；Mock Adapter 使比赛演示可复现。
- **工程可交接**：Vue 3 + TypeScript 前端、Go + Gin 后端、MySQL/Redis/MinIO 与 Compose 部署基线均有统一规范。

## 演示路径

1. 从 MD3 公开门户浏览组织动态、项目、资源与知识库。
2. 进入独立后台，创建/发布一条内容；回到门户验证只读展示结果。
3. 展示 QUTCraft Minecraft 风格门户读取相同 Portal API 的效果。
4. 从门户进入白名单申请入口；在后台审核；通过 Mock/RCON Adapter 展示受控服务器联动与审计边界。

## 预期价值

- 对组织：减少内容与资源分散，形成可交接的知识与项目资产。
- 对成员：明确参与入口、申请状态和协作责任。
- 对访客：获得可靠、具有组织特色且持续更新的公开门户。
- 对比赛：以 QUTCraft 真实需求验证通用平台能力，而不是只交付单一社团官网。
